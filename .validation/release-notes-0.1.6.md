# FoilPage 0.1.6

资料更稳、下载更顺、整理稿更好读，托管计费讲清楚。

本版把 0.1.5 之后陆续完成的多批更新合并在一次发布里：下载恢复、资料连续性与文稿备份、后端恢复修复、界面与图标，以及整理稿排版和托管计费的调整。

## 整理稿：更短的分段与重点加粗

- 整理稿默认使用短段落，每段 1-3 句，并用整句加粗标出核心判断或关键数据（每段 1-2 处）。
- 超过 3 句的正文段落会在句末自动另起一段。这一步只增加空行，不改任何字；小数点和分号不算句末，加粗范围内不拆。
- 实测（同一批素材重新整理前后）：短视频每段 3.8 句降到 2.1 句，中等长度 4.4 降到 2.3，1.8 万字长文 6.0 降到 2.4；加粗从 7、3、0 处增加到 18、55、78 处。
- 整理结果没通过保真检查时（模型写了原文没有的数字，或成稿明显短于原文），应用仍改用逐字排版的原稿。现在任务清单会记录触发原因，日志里有具体数量，便于排查长文偶发降级。

## 重新整理：过程文件清理后也能用

- 开启过「转写后删除过程文件」的任务，此前无法重新整理，会直接报文件不存在。
- 原始转写不在时，现在按转写引擎同一条拼接规则，从字幕分段逐字重建。只对仍保留分段文件的任务有效。

## 托管整理

- **标题优化计费**：由「按正文全文费率另计一次」改为固定 1 次基数，随所选档位的倍率计算。开启标题优化不再让积分消耗翻倍。
- **打开前确认**：托管模式下开启标题优化会先显示计费说明，需要勾选「我已知晓」；已开启时切换到托管同样会确认。自带密钥模式不弹窗。
- **长转写自动分段**：托管模式下单次请求受服务时限时约束，超过 6,000 字的转写会自动分段依次整理，避免单次请求超过服务端的时限。可用的分段数由服务端按字数给出。超出上限时会在发起任何请求前提示，预扣的积分退回。
- **模型推荐**：设置页「托管模型」下方按积分、速度和适用长度给出推荐，只列服务端当前在架的档位。所选档位被服务端下架后自动回到默认档。
- **在架档位**：本次服务端更新后，托管目录为 qwen-plus（基础积分）与 deepseek-flash（3 倍积分）。qwen-turbo 和 qwen-max 因上游配额未开通暂时下架，此前选择它们会失败并退款。
- 常见问题、套餐说明和用户指南同步更新了积分规则，并新增一条长视频整理的说明。

## 下载

- 抖音签名地址过期后自动重新捕获；定时重试不受扩展休眠影响；详情请求被拒时回退为刷新页面后自动补交。
- 在桌面端粘贴抖音分享短链，会先解析并通过后台标签页捕获，再走直连下载。
- 信息流里滑动出现的视频始终保留下载和转写入口；按钮被遮挡时移到页面固定位置。
- 被代理隧道拦下的任务，在隧道断开后自动重试，48 小时内每个任务最多 3 次。HTTP 412 和网络错误的提示会指向 VPN 或系统代理，常见问题与用户指南补充了分流域名清单。

## 修复

- **停止后台进程后无法再启动**：在设置里或通过 Agent 停止后台进程后，再次启动会失败并提示「应用未完成此操作」，环境检测里的 GPU 识别也同时失效，只能重启应用。原因是停止时借用的控制台改坏了主程序自身的标准句柄，现在停止后会原样恢复。该问题自 0.1.4 起存在。

## 资料与界面

- **资料连续性**：资料库有了稳定的身份和位置解析，桌面端、后台进程与 Agent 共用同一套规则。数据库或设置失联时停止写入并给出错误，而不是新建空库。导入备份分阶段进行，可回滚；重启时先完成未完成的恢复。
- **文稿备份**：新的备份格式带逐文件大小和 SHA256 清单，明确不包含视频、封面与模型实体，导出前要求后台任务已结束。
- **已知限制**：资料库里存在已登记但缺失的文稿引用时（例如旧版开启过「转写后删除过程文件」），文稿备份会拒绝导出并指出缺失项，而不是生成不完整的备份。找回文件或修复引用后可正常导出。
- 修改输出位置后，旧稿仍可在摘要、搜索、阅读与编辑中按原位置读取。
- 翻译与批量整理的运行记录保存在任务库里，应用重启后仍可查看最近的失败与待重试项；每次主动翻译使用新的运行标识，改稿后可以重做。
- 历史下载恢复不再被「最新 500 条」截断；未来版本写入的资料库会拒绝被旧版本打开，避免降级损坏。
- Agent 的任务与文稿列表支持游标分页，可遍历 200 项以上的资料；媒体重关联在访问文件前拒绝相对路径与网络路径。
- 新的回卷耳图标应用到桌面程序、浏览器扩展和安装程序。
- 界面：媒体浏览与文稿阅读流程打通；竖屏视频在紧凑窗口中保持可见；调整栏目宽度时保留视频位置与焦点；任务操作与选中反馈优化；视频历史索引更快；重试次数得到保留，并减少了重复的许可证校验。
