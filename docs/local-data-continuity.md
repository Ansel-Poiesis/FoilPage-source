# 本机资料、视频扫描与失败记录

本机资料归属于数据目录，登录、退出、切换账户和购买权益都不迁移或清空资料。默认数据根为 `%LOCALAPPDATA%\FoilPage`（1.3.8 品牌统一改名，桌面端首次启动会从旧根 `VideoToArticle` 原地重命名并在旧路径留下 junction 垫片，≤1.3.7 回滚版本仍按旧路径读写同一份数据；agent CLI 不做迁移，只在旧根尚存且新根不存在时回退解析旧根），数据库是 `library.db`；安装目录和源码目录与资料目录不同。诊断时只报告必要的路径、行数、摘要和文件存在数量，不输出完整设置、凭据、视频签名地址或正文。

任务页隐藏已归档的转写任务及其关联下载；归档不会删除视频或文本。文本库包括已归档任务，可清空搜索词和标签查看全部内容。源视频不在旧路径不会使已有原始转写或整理稿消失。升级前后比较应在 SQLite `mode=ro` 事务中核对 `jobs`、`download_jobs`、`media`、`manifests`，再单独核对实际文件；不能因为界面为空就覆盖数据库。

视频扫描默认读取 `download_dir`，`video_scan_directories` 可加入其他明确目录。`video_scan_recursive=false` 默认只读目录直接子文件；需要读子目录时显式打开。扫描不建立处理任务、不调用模型、不移动文件；媒体按路径、大小及修改时间复用已有索引，新内容摘要只计算一次。快路径会确认数据库行仍可用；文件曾标记缺失后以相同大小和修改时间回到原路径时，会清除缺失状态而复用原媒体行。目录读取在后台进行，现有视频仍可播放；进度只轮询扫描状态，完成后更新列表。单次最多 20000 个视频、深度最多 12 层，跳过链接、重解析目录、隐藏临时文件、空文件、最近仍在写入的文件和活动任务的源路径。扫描范围改变不代表原来的登记内容被删除；文件不可用仍保留记录。

增量索引的大小与修改时间是缓存条件，不替代强内容身份。修复旧路径必须确认候选的 SHA256 等于原媒体摘要；名称或大小相同只能作为候选。`MediaRelinker.preview()` 返回原位置、候选位置、受影响数量和 revision；`apply()` 在事务中再次核对 revision 与活动保护，只更新原媒体 ID、原任务和下载的路径。保留原文稿、历史 manifest、原下载根归属及全部文件，不将恢复到外部目录的文件误标成可删除的下载副本。结果的本地 `undo` 回执可通过 `rollback()` 恢复这一次路径修改；若随后任务或关联改变，拒绝覆盖当前资料。真实修复先查看预览，保留受保护备份，不自动全盘搜索或猜测匹配。

失败任务保留由 `failed_task_retention_days` 控制，`0` 默认永久保留并关闭该部分定期清理；`failed_task_cleanup_interval_hours` 默认 `24`。另一条独立规则默认开启：同 URL 后续下载成功的旧失败行（1.3.10 前一次点击可能积累的多条失败记录），由 `superseded_failure_retention_hours`（默认 `24`，`0` 关闭）到期自动清理；曾产出媒体、关联任务或文件的成功/失败行永不清除。开启后只删除超过保留期、仍为失败、没有媒体、下载文件、转写产物、manifest 或相关任务的空记录。正在下载或处理、已完成、取消及新失败记录继续保留。清理不删除任何视频、正文、模型或缓存文件；旧扩展提交 ID 留下取消标记，迟到重放不能重新建立被清理的任务。Agent 可先查询预览再按用户要求更改保留设置，不能把清理失败记录当作修复资料显示的办法。

开发测试只用临时合成目录和临时数据库。实际账户、资料目录、下载文件与正文不是测试夹具；禁止运行删除真实资料来验证清理。

## 2026-11-12 源码迭代状态

视频页源码新增扫描取消按钮。取消会停止后续枚举和摘要，不删除已登记视频或关联任务，也不在部分扫描后刷新全库缺失状态；之后可再次完整扫描。扫描缓存现仅在媒体行未标记 missing 时跳过重新登记，避免同进程文件恢复后仍显示缺失。以上为当前源码行为，安装版/加载态按各自版本指纹单独确认；同路径恢复行为未运行自动化验证。合成规模测量入口见本地扫描基准；该基准不替代真实用户备份恢复验收。
