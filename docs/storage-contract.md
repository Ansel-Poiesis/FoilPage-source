# 本地资料存储约定

2026-11-22 · TASK-5553 · 文件管理第一批实现。

本约定描述当前源码行为，安装版以对应构建与实际验收记录确认。普通版本升级保留用户的资料位置、身份和关联；本轮不重排已有文件，不执行整库搬迁。

## 位置与归属

| 内容 | 位置与规则 |
| --- | --- |
| 程序 | 安装目录，只放程序、依赖及随包资源；用户资料、模型和备份不能保存在这里或其子目录，包括指向这里的别名 |
| 任务库 | 默认 `%LOCALAPPDATA%\FoilPage\library.db`，保留已有自定义数据库位置；普通设置不能切换活动数据库 |
| 文稿 | 当前 `output_dir` 及任务记录的历史输出目录；原稿、终稿、译文、字幕和段落对照属于持久资料 |
| 托管媒体 | 既有 `download_dir`；文稿备份只列清单，不含媒体副本 |
| 外部原件 | 保持原位置及既有引用方式；文件失联保留记录，使用明确的媒体重关联操作 |
| 缓存、日志与模型 | 分别沿既有清理与下载设置管理，不能把仍被引用的文稿或媒体视为缓存 |

已有 `VideoToArticle` 根继续使用，普通启动不再重命名。空的 `FoilPage` 目录不会遮蔽旧资料；两处都是不同的真实资料根时停止自动选择。两个路径是同一目录的 junction 别名时归一化。Desktop、Worker 与 Agent 共用默认资料根解析；正常桌面链路由明确的设置目录定位，不按程序版本或工作目录猜测。独立 Worker 可通过显式 `--db` 使用既有库；同时指定设置目录时必须与其中的数据库位置一致。

独立开发通过 `--data-dir` 使用明确的合成目录；其日志也写入该目录，不借用正式资料根。

## 资料库身份和失联保护

SQLite 的 `library_identity` 是稳定资料身份，设置的 `library_id` 是本配置预期打开的身份。首次成功打开旧格式库时补一次身份，不重编号任务或媒体。一个 `.library-initialized` 文件只标记此配置目录已经成功开过库，防止设置被删除后误认为首次使用；它不保存第二份路径、正文或凭据。

绑定后的数据库缺失、身份不符、初始化过的配置缺失、配置不可读或已完成设置的旧库失联时，启动停止写入并给出错误。没有既有资料的干净配置可以正常创建新库，包括明确配置的自定义位置。对于升级前没有身份与初始化回执的旧配置，只能依据仍存在的数据库、设置完成记录和产物判断，不能保证识别所有被外部删除的历史。

双根冲突通过显式 `--data-dir` 选择，不按大小、修改时间、应用版本或相同来源身份自动合并。媒体和任务沿用既有 ID。普通设置不能修改活动库身份或数据库路径；恢复备份负责同步被恢复数据库与设置的身份，回滚同时恢复两者。

## 历史文稿与目录设置

修改 `output_dir` 只决定以后产物的位置，不搬已有文件。正文、译文、摘要、搜索和 Agent 编辑共用当前输出根或该任务确切历史输出目录的校验。它不授权读取历史根中的任意文件。

备份包含当前输出根的文本，以及历史任务目录和登记的文本引用。不同历史根使用独立的备份命名空间，防止同名文件互相覆盖。恢复时把所有已登记文本和任务输出根映射到本机输出根下，保留历史分组。外部视频原件的位置不在该恢复范围内。

## 文稿备份与恢复

“导出文稿备份”包含：SQLite 一致副本、脱敏设置、当前和历史文稿、字幕、段落对照、译文，以及模型/下载清单。视频、封面、模型实体不在包内，换机后可能需要重新关联原视频或重新下载模型。

导出要求 Worker 已停止、翻译/批量整理已结束、下载已停止写入，否则报错，不自动等待或停止任务。进程内沿用现有锁，SQLite 写入门禁阻止其他数据库写者开始发布。数据库与文件作为同一集合归档。绕过程序的外部编辑不受数据库锁控制，导出会检查文件变化并验证最终包的摘要。

新包为 `document_backup` 格式，清单记录资料身份、范围、输出映射以及逐文件大小和 SHA256。写入同目录临时包，验证后才替换目标。文件缺失、不可读取、被修改或归档失败时返回错误，保留上一份有效备份。成功结果明确返回 `includes_media:false`。

恢复先核验包的安全路径、完整清单、摘要、数据库与引用，再调用既有带阶段日志的恢复流程。旧格式备份仍沿原有结构导入；旧格式没有逐文件摘要，不声称具有新格式的完整性证明。未来格式拒绝导入。成功导入后重开完成资料身份及真实文稿读回核验。

已登记文件缺失时，本轮不提供伪装成完整备份的导出。旧版“删除过程文件”曾留下指向已删除原稿的引用，此类库会明确报缺失；导入前保护备份也遵守同一规则。应保留故障现场并找回缺失文件，不能靠新建空库或清空引用掩盖问题。本轮尚未实现单独的救援导出。

若正常启动因原库缺失而停止，先检查原磁盘、目录与设置备份，不删除剩余文件。需要从已有包恢复时，可在明确的新建独立资料目录启动应用，再通过设置导入备份；恢复后保持使用这个明确目录，确认文件与关联，再决定后续搬迁。不要把故障目录复制覆盖到仍在运行的数据库。

## 后续能力

受控整库迁移、包含媒体的整库备份、自动周期快照和用户资料回收区尚未在本批实现。现有删除与缓存清理仍按各自明确操作执行，不因新增存储约定而自动删除、合并或搬动文件。
